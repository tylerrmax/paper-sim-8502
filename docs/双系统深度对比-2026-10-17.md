## 二、架构对比

### 2.1 数据流

**8502**:
```
行情源（腾讯/Binance/新浪）
  → engine/pipeline.py（信号生成）
  → engine/sim.py（撮合/账本）
  → db/sim.db（15表，直写）
  → app.py（直读DB渲染）
  → GitHub推送（公网同步）
```

**验证终端**:
```
VM管线 → /tmp/sim_snapshot.json
  → git_sync.py（2分钟轮询）
  → snapshot.json（62KB）
  → git push → Streamlit Cloud拉取
  → app.py（读快照渲染）
指令反向：页面 → GitHub API → commands/pending/ → 轮询取回执行
```

**分析**: 8502是直连架构，数据链路短；验证终端是快照中转架构，多一跳就有滞后和故障点。验证终端的指令通道（GitHub API写文件+轮询）延迟约2分钟，且`paper-sim-git-sync`任务近期多次超时（T T T T T），可靠性存疑。

### 2.2 部署方式

| 项 | 8502 | 验证终端 |
|----|------|----------|
| 仓库 | tylerrmax/paper-sim-8502 | tylerrmax/paper-sim-web |
| 分支 | master | main |
| Cloud应用 | paper-sim-8502-4n7zkwjzuybpyk5xfrte3 | paper-sim-web-gvrnhdtbzruqqp7rcczvej |
| 推送方式 | 代码直推，Cloud自动重部署 | 数据sync推送（fba0fdc等纯sync提交） |
| 本地运行 | `streamlit run app.py --server.port 8502` | 无本地直连模式 |

### 2.3 外部依赖

| 依赖 | 8502 | 验证终端 |
|------|------|----------|
| 行情实时源 | 腾讯qt.gtimg.cn、Binance API、新浪图表 | 无 |
| GitHub API | 代码推送 | 代码推送+指令通道 |
| Streamlit Cloud | 是 | 是 |

**8502唯一外部依赖**：行情源 + 用户人工券商下单（符合"绝对独立五维"设计）。

## 九、已知问题/技术债

### 9.1 8502（P0）

1. **sim_hk账本历史污染**（未修复）：
   - HK0354：positions 0 vs fills净-24,000
   - HK9660：positions 8,300 vs fills净-4,200（差12,500）
   - 独立重放得负持仓，历史成交不闭合
   - 影响：港股累计收益不可信，需定位最早分叉点后做幂等迁移

2. **sim_crypto账本污染**（未修复）：
   - BTCUSDT：positions 0 vs fills净-0.4

3. **策略版本生效日隔离缺失**：仅有strategy_version字段，无生效日期，回填仍有污染风险

4. **关注列表不持久化**：仅st.session_state，刷新丢失

5. **TradingView国内被墙**：已降级为备选，主用新浪

### 9.2 验证终端

1. **快照滞后**：架构性缺陷，无法根除
2. **指令通道延迟**：约2分钟，且git_sync多次超时
3. **策略版本陈旧**：draft-2026-10-02，未同步v1.0
4. **功能冻结**：仅数据sync，无功能迭代

### 9.3 对比结论

8502的问题是**数据质量债**（历史账本污染），可修复；验证终端的问题是**架构债**（快照滞后），不可根除。
